Engine command reference

Generated directly from extension/core/engines.js — the same data the extension uses, so it cannot drift from the code.

The transport is JSON for every engine. Only the vocabulary differs.
  • MCP is JSON-RPC and every tool declares JSON-Schema'd parameters, so the plain-text {"command":…,"params":{…}} envelope is already the native format of the thing on the other end.
  • A per-engine wire format would fork the parser, the camouflage masking and the parse-error recovery for no capability gain.
  • What actually broke non-Roblox sessions was teaching Roblox's one-tool-per-action vocabulary everywhere. Unity is action-dispatch; Godot needs camelCase projectPath; Blender needs JSON-escaped code.

Roblox Studio — unchanged vocabulary, corrected shapes

Roblox Studio

flat, one tool per action

The JSON transport and this vocabulary are deliberately untouched by 6.17.0. Every place-scoped command also takes studio_id (get it from list_roblox_studios). Any other MCP server

Unreal, Figma, custom servers

discovery-first

Their command sets are not documented in the prompt on purpose — guessing a package or tool name is how you get a hallucinated API. The extension emits a discovery-first rule instead: run list_mcp_servers, then list_commands with that server's id, and use only what it advertises. If a tool's schema shows an action parameter, the action goes inside params.action — it is not a tool name of its own.
