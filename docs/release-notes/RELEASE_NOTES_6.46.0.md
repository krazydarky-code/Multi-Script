# Multi-Script 6.46.0 Dev

Ultra now checks the actual execution path. Substantial native builds research
available references and load a full relevant method before implementation.
Repeated identical inspections and failed calls are bounded, preventing the
endless empty-place loop. Missing visual/motion evidence gets one reminder and
then an honest review state. Small local assets stay quick. All six effort levels
deliver their active method even when enhancement is off. All 904 skills retain
their IDs and receive revised domain-specific execution, recovery and evidence.

Chat studio isolates connected engines from its prompt, catalog and dispatch.
Arena waits for both candidates/response selection before sending tool feedback;
results remain unmodified and uncertain sends are never replayed automatically.
Prompt metadata no longer asks a model to impersonate a different backend.
Roblox inspection survives restricted Lighting properties, schema repair maps
unambiguous path aliases to target_file, and errors give specific Color3 and
capability guidance. Task IDs survive the initial chat URL change; the progress
tool can read the actual ID before reporting updates.

The supplied stud-creature library and Roblox service/style guide are available
as scoped full resources through ms_skill_reference, with attribution and licenses.
PlazCode UltraLab patterns are rewritten for Multi-Script's architecture. No
foreign binaries, mandatory UI style or updater are included.

Task progress and phone control are compact chatbar icons. The run monitor shows
automatic response stages for direct replies or a concrete reported plan for
complex work, with the current stage, remaining tasks, elapsed time and rough
ranges when step data supports them. Tool chips do not complete project checks.
Estimates pause on blockers/errors/Stop and are withdrawn when timings overrun.
Restored ledgers preserve timing and remain paused until work resumes. Settings
stays on-screen even when the composer is near the top of the viewport.

The paired LAN phone interface receives the same status and supports queued
follow-ups, pause/resume, Stop receipts and revocation. Its real HTTP interface,
broker, worker and content-script queue are covered by headless Chromium tests.
