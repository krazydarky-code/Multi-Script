# Multi-Script — Roblox animation production

Adapted production methods, not model-weight training or new permissions. User scope, the inspected project and exact live schemas govern. Reference screenshots and example asset IDs are not imported assets or verification.

## Inspect

Identify the exact target rig and classify the job as authored clip, playback controller, locomotion, combat, tool alignment, NPC/creature, IK/procedural overlay, face, cinematic or diagnosis. Read the actual joint/bone graph, scale, rest transforms, Humanoid/AnimationController/Animator, Animate script, assets, remotes and competing controllers. Distinguish R6, R15, custom rigid and skinned rigs; never assume human part names on a creature. Record asset ownership/permission and whether the clip is local editable source or a usable published asset. Select the real server/client execution context and exact tool schema; a connection label is not rig inspection. For the supplied block/stud creature and equipment references, infer only visible proportions, articulated regions and silhouette constraints. Static pictures do not establish a gait, clip length or transition. Inspect the real rig, joint axes, support contacts, controller, asset ownership and existing motion language before choosing how the character should move. Identify the parts intended to remain rigid: brick body pieces, paws/hooves, jaw, ears, wings and tail segments. Determine which pieces are skinned, bone-parented or joint-driven in the target pipeline. Preserve useful existing clips, named markers and controller paths instead of rebuilding the rig merely to match a still image.

## Design

Plan anticipation, decisive contact/action, follow-through and recovery with clear silhouette at the gameplay camera distance. For locomotion define gait phase, planted contacts, stride/cycle speed and a compatible loop seam. For combat define startup, authoritative active interval, recovery, interruption and return to locomotion. Create a manifest of purpose, rig, actual asset ID or explicit unavailable placeholder, priority, loop, fade/speed, markers and permitted owner. Decide which layer owns movement, pose, camera, audio, VFX and damage. An authored root displacement is not automatically authoritative world travel. Use references for timing, weight and arcs without copying another rig's channels or inventing a published upload. Extend the current pose language with an action sheet: intention, support, anticipation, key pose, contact and recovery. Keep the creature's identity readable at gameplay distance and decide where rigid overlap is acceptable. Plan how body mass, stride and tail/ear follow-through communicate weight without stretching every brick form. For UI and rewards, define closed/opening/open/closing and focus/press/pending/result transitions in the existing controller. Choose a restrained motion hierarchy: panel movement explains navigation, a small button response confirms input, and stronger celebration follows actual success. Timing is authored and tunable; reduced motion uses a stable alternative.

## Build

Author/reuse editable clips on the actual rig and keep their source. Integrate with the server-created/replicated Animator after the rig is in Workspace; load through Animator:LoadAnimation and cache tracks per rig lifetime instead of loading on every trigger. Set purposeful priority, loop, weight and fade behavior. Length may be zero while loading, so timing must not assume immediate availability. Track one owner per transform/channel; procedural overlays and IK must respect the animation evaluation phase and current rig APIs. Feature-check modern graph/constraint APIs against the installed Studio documentation before adopting them. Graph parameter names/types come from the actual authored graph; Speed and Grounded are examples, not universal built-ins. Avoid replacing a working Animate/controller just to add one action. Block the key poses and ground contacts before smoothing curves. Check that feet or hooves support the body, limbs enter the torso cleanly, and jaw/wing/tail rotations do not expose gaps or intersect neighboring pieces. Add secondary motion only after the primary action and loop seam work at normal playback speed. Use the target's existing animation/state system and give each transform one owner. For UI scale or position feedback, cancel or retarget the previous tween rather than stacking repeated tweens. Do not animate expensive text-outline thickness or permanently run a frame callback for a one-shot interaction; keep the original resting transform recoverable.

## Integrate

Player presentation may start responsively on the owning client using the correctly replicated Animator; non-player animation that must replicate is loaded/started on the server. Verify the actual ownership setup rather than generalizing a solo test. Bind marker signals before playback and use named markers for cosmetic timing. Damage, cooldowns, inventory and hit validation remain server-owned and must not trust a client marker or animation ID. Blend locomotion/actions with explicit entry/exit/interruption rules. Cache and disconnect marker/track signals; distinguish playback stopping from complete fade-out when cleaning up. Cinematics own a cancellation token, saved camera/control state, render binding and one cleanup path for normal finish, error, death, respawn and replacement. Align weapon grips/attachments to the actual hand and rig rather than eyeballing an unrelated asset. Use named animation events for presentation timing and disconnect their listeners with the rig/controller lifetime. Coordinate footstep, impact, trail and reward effects through shared event contracts with the existing audio/VFX skills. Consequential gameplay remains authoritative, independent of whether a client animation marker was observed. Handle action replacement, input reversal, death/respawn, owner removal and missing assets through one cleanup path. A rapidly reopened panel must end in the newest requested state; an interrupted creature action must blend or return to the actual rest/locomotion pose without retaining offsets or orphaned tracks.

## Verify

Play the real clip/controller at normal and slow speed on the intended rig. Check contacts, arcs, deformation extremes, loop seams, foot sliding, priority/weight transitions and repeated triggers. Exercise locomotion → action → interruption → recovery, equip/unequip, jumping/falling/landing, death/respawn, target destruction and missing/denied assets. Use a multi-client/server test for replication claims and test in the published ownership context when asset permissions matter. Inspect logs, active track/connection counts and repeated NPC density. Capture a short recording or equivalent temporal evidence; a single still frame cannot prove a transition. Report clip source, real IDs, controller paths, ownership decisions, tests and unresolved publishing/device checks separately. Read final source back and use an advertised syntax/analysis tool or an actual Luau compiler when available. Requiring a ModuleScript runs it and is not a compile-only check; unavailable restricted compilation stays explicitly unverified. Inspect a recording or sampled pose sequence on the target rig from front, side and normal gameplay camera. Check contact, silhouette, weight, loop closure, root drift, rigid-piece gaps and extreme poses. Reimport the exported clip before claiming that bones, weights and animation survived the delivery pipeline. Test repeated open/close, hover/focus/press reversal, interruption halfway through, low frame rate and reduced motion for animated interfaces. For characters, test locomotion-to-action-to-recovery, competing layers and respawn. Verify that track/listener/tween counts settle after teardown and that missing or denied assets have clear recovery.

## Failures

No playback: inspect asset permission, loading errors, Animator ancestry/Workspace presence and rig compatibility. Track time advances but pose does not: inspect actual channels, priority/weight and competing transform writers. Owner sees it but peers do not: verify server-created Animator, correct character/owner, NPC server playback and a real multi-client reproduction. Popping/foot sliding: compare rest pose, loop seam, contacts, movement speed and fades before adding keys. Missing marker: verify exact case/name, signal hookup before playback, loop/retrigger behavior and early stop. IK instability: inspect chain, target/pole reach and blend/cleanup. Cutscene leaves a Scriptable camera: repair the shared exit path. Never bypass restricted capabilities, fabricate IDs or claim that a local KeyframeSequence was published; preserve source and provide an explicit upload/permission handoff. If motion feels floaty, inspect support duration, center-of-mass shift, anticipation and recovery before adding more keys. If a block creature deforms like rubber, revise weighting or rigid articulation within the existing rig. If UI motion feels chaotic, remove competing transform owners and unnecessary simultaneous movement rather than deleting all useful feedback. If an interrupted transition ends in the wrong pose or visibility state, inspect stale completion callbacks, cancellation tokens and restoration ownership. A still render does not verify motion, and an editable local clip does not prove successful asset publishing or replicated playback. Preserve source and report the remaining exact check.
